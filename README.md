# DiskWhy

DiskWhy 是一个 Windows 磁盘空间分析和清理工具：不只告诉你 C 盘哪里大，还把已用空间的每一块都讲清楚——这是什么、属于哪个软件、为什么在、删了会失去什么、能腾多少、怎么安全腾出来；读不到的部分（无权限、系统保留、云端占位、说不清的）单独列出，不悄悄少算。清理动作带护栏、默认可撤销。

当前进度：**阶段 D**（带护栏的动作）。各阶段验证记录：[PHASE_A](docs/PHASE_A.md)（扫描 + 归属）、[PHASE_B](docs/PHASE_B.md)（解释引擎）、[PHASE_C](docs/PHASE_C.md)（方块图 + 去重 + 快照）、[PHASE_D](docs/PHASE_D.md)（清理动作与护栏），本机覆盖率见 [docs/coverage.md](docs/coverage.md)，总体计划见 [PLAN.md](PLAN.md)。

## 功能

- **扫描**：多线程扫描整个盘或某个文件夹；按簇取整的“实际占用”；硬链接和商店应用目录映射只算一次；不跟随链接；云占位文件只读属性不打开。
- **归属**：已扫描 / 无权限（推算）/ 系统保留 / 云端占位 / 未归属，加起来等于卷已用空间。
- **解释**：198 条规则（Windows 系统、浏览器、开发缓存、AI 模型、国内常用软件等）+ 内容启发式 + 可选的 AI 推测（默认关闭，只发名字和大小，不发内容）。三档：可以放心清理 / 需要你来判断 / 建议保留；认不出来的显示“未知”并列出线索。
- **方块图 + 列表**，快照保存 / 打开。
- **清理清单**：“可以放心清理”和“需要你来判断”的项可以加入清单；预览里逐条列出真正会删的文件（前 200 条 + 总数）、跳过的文件和原因；输入合计 GB 数确认后执行。
- **删到哪里**：回收站（默认）；或隔离到其他盘 / 其他文件夹（保留 7 天，可以整批还原，也可以二次确认后彻底清空）。
- **建议保留 / 只能用工具清的项**：不给删除按钮，给出“该怎么腾”：可复制的命令（DISM、`powercfg /h off`、`cleanmgr`、`conda clean` 等，DiskWhy 不替你运行）、系统存储设置入口、迁移到别的盘的步骤（微信 / QQ 存储位置、Docker Desktop 磁盘位置、`wsl --export` 等）。
- 每次动作后只重新扫描受影响的文件夹，列表和方块图立即更新；每个动作写进 `%LOCALAPPDATA%\DiskWhy\actions.log`。

## 安全承诺（清理动作的全部护栏）

1. **档位门槛**：只有“可以放心清理”和“需要你来判断”的项能进清理清单；“建议保留”、“未知”、AI 推测的项一律不能删；规则说“应该用工具清理”的项也不能直接删。判断由后端按当前扫描结果和规则库重新做，不信任界面传来的任何说明。
2. **保护路径硬编码，不能配置、不能关闭**：任何卷根；`Windows`（含 `WinSxS`、`Installer`）；`Program Files*`；`ProgramData\Microsoft\Windows`；桌面 / 文档 / 图片 / 视频 / 音乐 / 下载的根目录和它们下面第一层（含重定向后的真实位置）；`.ssh`、`.gnupg`、`.aws`；OneDrive 根目录；`$Recycle.Bin`；`System Volume Information`。落在这些路径本身、里面或者是它们的上层文件夹都拒绝。比较前统一大小写、`\\?\` 前缀、`/`、结尾的点；拒绝 `..`、网络路径、数据流；展开 8.3 短文件名；解析路径里的链接，指到受保护目录的也拒绝。
3. **规则一致性**：要删的路径必须真的被那条规则命中（或者在规则命中的文件夹里面），不允许拿规则去删它的上层文件夹；加入清单后规则变了也会拒绝。
4. **30 分钟内修改过的文件跳过**，并在预览里列出。
5. **云端文件 / 占位文件跳过**，而且不打开（不会触发下载）。
6. **链接不跟随**：联接、符号链接只删链接本身，指向的内容不受影响；预览里明确标出。
7. **被占用的文件只报告、不关程序**：用 Restart Manager 列出占用它的进程名和 PID；你可以选“跳过被占用的”继续，或者取消。
8. **空间提示**：用回收站而所在盘可用空间不到 10% 时提醒“回收站在同一个盘上，要清空回收站才会腾出空间”，并提供改成隔离的入口；隔离区位置写不进去、空间不够时直接拦下。
9. **执行前重新校验**：每个文件在执行前再核对一次文件 ID、大小、修改时间，和生成清单时不一样（被改过或替换过）就跳过。
10. 默认进回收站；隔离区跨盘时“复制 → 逐字节比对 → 再删原文件”；清单项本身的文件夹保留，只删处理完后变空的子文件夹；某一条失败不影响其他条，已成功的不回滚，报告里写清楚；每个动作都有日志。
11. 本阶段**不自动运行任何系统命令**（DISM、powercfg、cleanmgr、conda 等只展示、可复制）；只会打开白名单里的系统设置页。

## 已知限制

- 只支持本地盘符路径（不支持网络路径）；普通用户权限下部分系统目录读不到（计入“无权限”），以管理员身份运行没有经过验证。
- 回收站是否成功按“执行后原位置已经没有这个文件”判断；如果某个文件太大进不了回收站，系统会弹出“将永久删除”的警告（DiskWhy 请求了这个警告），请看清楚再点。
- 很多机器上普通用户不能在盘的根目录（如 `D:\`）建文件夹，这时隔离区请选“其他文件夹…”。隔离区里的文件 DiskWhy 不会自动删，超过 7 天只会提醒。
- 跨盘隔离时链接只能直接删掉（链接本身不占空间），还原时无法恢复链接。
- 很大的文件夹（几十万个文件）预览会比较慢；单项超过 50 万个文件会被要求拆开分批。
- 86 条规则的默认路径没有在装了对应软件的机器上核实过（见 PHASE_B）。

## 目录结构

```
crates/diskwhy-core   扫描、归属、解释、清理动作（纯 Rust 库，不依赖 Tauri，带测试）
rules                 规则库 TOML（编译期嵌入；另可放 %LOCALAPPDATA%\DiskWhy\rules\*.toml）
crates/diskwhy-cli    命令行 diskwhy-cli
src-tauri             Tauri 2 桌面壳（只做 IPC 转发）
src                   Vue 3 + TypeScript 前端
docs                  阶段验证记录与截图
```

## 环境要求

- Windows 10/11 x64（回收站用到的 `FOFX_RECYCLEONDELETE` 需要 Windows 8 以上）
- Rust（MSVC 工具链，已在 1.93 上验证）
- Node.js 22 + npm 10
- WebView2 运行时（Windows 11 自带）

## 构建与运行

```powershell
# 测试（核心库 + 命令行 + 桌面壳）；跨盘隔离测试需要另一个盘上可写的文件夹
$env:DISKWHY_TEST_XVOL_DIR = "D:\某个可写的文件夹"
cargo test --workspace
npx vitest run

# 命令行：扫描 C 盘，打印前 30 大目录和归属统计，并导出 JSON
cargo build --release -p diskwhy-cli
.\target\release\diskwhy-cli.exe scan C:\ --top 30 --json out.json

# 桌面程序（开发模式）
npm install
npm run tauri dev

# 桌面程序（发布版，产物在 target\release\diskwhy.exe）
npm run tauri build -- --no-bundle
# 启动后直接扫描某个文件夹：diskwhy.exe --scan D:\some\folder
```

命令行解释：`diskwhy-cli explain C:\ --top 50 [--json out.json] [--md coverage.md]`。其他参数：`--json-depth N`、`--mode exact|fast`、`--threads N`、`--keep-files N`、`--quiet`、`--snapshot 文件`、`--from 快照`。
