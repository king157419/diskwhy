## 共享布局
- **首页**：左重右轻。左边"可放心清理"+ 大数字 + 按分类拆分的一行小字 + 主按钮「清理 32.1 GB」+ 文字链接「看看都是什么」；右边是 **C 盘竖向容量柱**，从上到下：剩余 14.0 → 可放心清理 32.1 → 需你判断 49.6 → 其他 103，**每段右边直接写名字和数字**，再加一条虚线"清理后剩余 46.1 GB"。C 盘读数 80px。可点：清理、看看都是什么、设置，共 3 个。
- **清理页**：左侧分类是纯文字行（名字 + 大小 + 一条细条：绿=可放心、橙=需你判断），选中只加左竖线和加粗；右边是表格式列表，没有卡片——列头「名称 / 位置 / 大小」，按「可放心清理」「需你判断」分组，行高 50px，1px 分隔线，路径用等宽字体，需你判断的行名后面跟**后果标签**；ⓘ 改成整行展开（这是什么 / 删了会怎样 / 怎么清，文案直接取规则）。底部通栏：已选 17 项 · 可释放 32.1 GB · C 盘剩余 14.0 → 46.1 GB · 主按钮。
- **空间分析**：左方块图（两层：C 盘顶层文件夹 → 子项，颜色 = 三档），右列表（当前选中的"用户\king"的 15 个子项）。行 = 色点、图标、名字、灰色类别（≤8 字）、细条、大小。混合文件夹用空心点，排在最后。右上可切「方块图 / 并排 / 列表」。
- **确认弹层**：一行标题「清理 18 项」、一个总数 36.2 GB + 「C 盘剩余 14.0 → 50.2」、可收起的清单（需你判断的项置顶高亮，其余按分类一行）、「跳过 4 项 · 正在使用 ›」一行、**只有清单里有需你判断的项时**才出现勾选「我知道这些删了的后果」、一个主按钮（没勾时禁用）。

## 三套主题
**A 浅色 · 纸本**
- 感觉：暖白纸面 + 墨黑字，像一本排版讲究的杂志，而不是系统设置页。
- 色板：背景 `#F3F1EC` / 表面 `#FBFAF7` / 文字 `#1C1B18` `#5F5B53` `#99948A` / 强调 松绿 `#1F6B50`。
- 三档：可放心 `#2A7A5A` / 需你判断 赭石 `#BC7A22` / 先别动 暖灰 `#CBC4B7`；剩余 = 斜线。
- 字体：大数字 Instrument Serif（单位 GB 用斜体），界面 Geist + MiSans。圆角 6px。
- 装饰：极淡的纸纹噪点、1px 分隔线；按钮只有一个轻投影。

**B 深色 · 暖炭**
- 感觉：深棕炭底上一抹香槟金，像夜里的仪表盘；安静、不刺眼。
- 色板：背景 `#14110E` / 表面 `#1B1713` / 文字 `#F3ECE2` `#B6AB9C` `#7E7468` / 强调 香槟金 `#EBC47A`。
- 三档：可放心 = 金 `#EBC47A`（唯一发光的颜色）/ 需你判断 珊瑚 `#E3876B` / 先别动 `#4A4138`；剩余 = 暗斜线。
- 字体：大数字 Geist 200（极细，暗底上细字更亮），界面 Geist + MiSans，路径 Geist Mono。圆角 8px。
- 装饰：细噪点、金色段和大数字各一层柔光，其余全靠明度分层。

**C 趣味 · 汽水**
- 感觉：青柠 + 墨黑 + 米白，粗描边 + 硬投影，像贴纸和漫画分镜；结构与 A/B 完全一样。
- 色板：背景 `#F4F0E6` / 表面 `#FFFFFF` / 文字 `#141412` `#46433D` `#86817A` / 强调 青柠 `#D4F24C`（主按钮是黑底青柠字）。
- 三档：可放心 青柠 / 需你判断 西柚 `#FF8A76` / 先别动 `#D6D0C1`；剩余 = 波点，混合 = 斜条纹。
- 字体：大数字 Bricolage Grotesque 800（窄体），中文标题和标签用霞鹜文楷粗体，正文仍是 MiSans。圆角 12–18px，描边 2px。
- 装饰：首页左侧大色块 + 飞出的文件块小插画；选中态、弹层、容量柱都带 4–6px 硬投影。

## 后果标签对照表（替代"有代价"）
只在「需你判断」的项上出现；一项只挂一个，按**最坏的那个后果**选（找不回来 > 影响修复 > 需你确认 > 要重装 > 要重登录 > 功能变少 > 要重下载 > 删了变慢）。「找不回来」是实心标签，其余是浅底。数量是对 `rules/*.toml` 里 72 条 review 规则的 `lose` 文案做的关键词粗分，正式上线要逐条人工标注。

| 标签 | 规则 `lose` 里说的是 | 例子（规则 id） | 粗分条数 |
|---|---|---|---|
| **找不回来** | 删了就没了 / 可能丢本机独有内容 | recycle-bin、claude-code-data、aclos-highlight-videos、maven-repo | ~10 |
| 影响修复 | 以后卸载 / 修复 / 回滚会失败或要重下安装包 | package-cache、windows-old、nvidia-driver-installers、windows-logs | ~6 |
| 需你确认 | 规则写着"我不确定"，或文件夹里混着能删和不能删的 | codex-runtimes-cache、wechat-files-cache、dot-cache-root、keras-models | ~22 |
| 要重装 | 删了这个工具 / 扩展就用不了，要重新装 | rustup-toolchains、npm-global、vscode-family-extensions | ~7 |
| 要重登录 | 删了要重新登录、丢本地设置（聊天记录在云端） | wechat-appdata、qq-appdata、feishu-larkshell | ~9 |
| 功能变少 | 某个功能会关掉或暂时不能用 | hiberfil（不能休眠）、chrome-on-device-model | 2 |
| 要重下载 | 能下回来，但很大、很慢 | huggingface-hub、ollama-models、outlook-ost、node_modules | ~10 |
| 删了变慢 | 会自动重建，只是下次要等 | rust-target（启发式）、visual-studio-cache | 1 + 启发式 |

实现建议：在规则里加一个显式字段 `lose_kind = "redownload" | "slower" | "relogin" | "reinstall" | "repair" | "irreversible" | "feature" | "unsure"`，不要在前端按关键词猜（粗分时 `vscode-family-extensions` 就被误判成"找不回来"）。

## 实现时最难的 3 点
1. **中文字体的包体和许可**：MiSans 不建议子集化，整套常用字重打进安装包会明显变大；要么接受体积，要么中文改用可子集化的 Noto Sans SC（观感略"系统"）。三种展示字体只用到数字，子集化后可忽略。
2. **容量柱标签防重叠**：四段比例随机器变化，"剩余"只有几 GB 时段高可能只有十几像素。需要一个标签避让算法（最小段高 + 标签上下挤开 + 引线），否则又回到"看不清"。方块图的小块标签同理（现在的规则：宽 >62 且高 >40 才写名字）。
3. **后果标签的数据来源**：现在规则只有自由文本 `lose`，要为 ~72 条 review 规则和启发式逐条补 `lose_kind`，并决定"多个后果取最坏"的顺序；否则 UI 只能退回笼统的"有代价"。另外三主题共用布局意味着所有尺寸要由 token 驱动，C 主题的 2px 描边和硬投影会吃掉 2–6px，需要在组件里预留，而不是给 C 单独写一套布局。
