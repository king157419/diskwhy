### 1.2 最大的问题：商店应用的 AppData 重定向被说成了“Claude 的数据”（10 条 ❌）

`C:\Users\king\AppData\Local\Packages\Claude_pzs8sxrjxfjjc`（17.68 GB）整个被规则 `claude-desktop-data` 说成“Claude 桌面版的登录信息、设置、界面缓存、虚拟机镜像”。实际打开看：

- `LocalCache\Roaming\Claude`（10.09 GB）确实是 Claude 自己的数据；
- `LocalCache\Local`（7.56 GB）里是 `.dartServer`、`pip`、`ms-playwright-mcp`、`vitest`、`GitHub CLI`、**`DiskWhy-build`（7.01 GB，本项目的 Rust 编译目录）**……都是**在 Claude 里跑的程序**写的。

原因（[Microsoft Learn：Understanding how packaged desktop apps run on Windows](https://learn.microsoft.com/en-us/windows/msix/desktop/desktop-to-uwp-behind-the-scenes)）：打包成 MSIX 的桌面程序在 AppData 下**新建**的文件和文件夹，会写到“每用户、每应用”的私有位置（就是 `Packages\<包>\LocalCache\Local|Roaming|LocalLow`），再合并显示在真实 AppData 里；商店版 Claude 启动的 Claude Code 以及它执行的命令都是它的子进程，所以也被重定向进来。文档还写明：**卸载这个包时 Windows 会把这些重定向的文件一起删掉**——这对用户很重要（卸载 Claude 会顺手删掉别的工具的缓存 / 编译目录）。

修复（引擎 + 规则，不是只改文案）：

1. `ExplainCtx::msix_redirect()`：`%LOCALAPPDATA%\Packages\<包>\LocalCache\{Local,Roaming,LocalLow}\<其余>` 映射回 `%LOCALAPPDATA%|%APPDATA%|%USERPROFILE%\AppData\LocalLow\<其余>`，**按真实路径匹配规则 / 启发式**，并加一句提示“它和 AppData\… 是同一份；卸载「Claude」时 Windows 会一起删掉”。继承也改成只从同样在 LocalCache 里的上层继承（`ExplainCtx::inherited()`），不会再越界继承“某商店应用的数据”。认不出来的就老实标“未知”，线索里写明真实位置。
2. 全盘汇总（`tier_summary`）同样按真实路径归档，和列表说明一致。
3. 规则：`claude-desktop-data` 只管 `%APPDATA%\Claude`；新增 `claude-desktop-package`（包文件夹本身，self）、`msix-localcache`（LocalCache 和其下三个区，self）；`store-apps-data` 的 why 改正（原来写“商店应用不能随便往别处写”，对打包的桌面程序不成立）。
4. 启发式：Rust 编译产物改用 cargo 的标记认（`.rustc_info.json` + `CACHEDIR.TAG` / debug / release），不再要求文件夹叫 `target`、旁边有 `Cargo.toml`（`CARGO_TARGET_DIR` 可以叫任何名字）；子文件夹沿用上层判断。

修后：`DiskWhy-build\target`、`\debug`、`\debug\deps`、`\release`、`\release\deps` → 启发式 `rust-target`（review，“删了下次重新编译”）；`DiskWhy-build` → “里面几乎全是 target：Rust 编译产物”；`LocalCache\Local\pip\cache` 这类 → 按 `%LOCALAPPDATA%\pip\cache` 的 safe 规则说明。

副作用（诚实说明）：C 盘“规则未覆盖”从 13.95 GB 升到 21.22 GB、review 从 59.72 GB 降到 49.47 GB——原来这 7 GB 多被错误地记在 `claude-desktop-data`（review）名下，现在归到真实位置后规则库管不到（DiskWhy-build 只有启发式能认，而全盘汇总只算规则）。这是**更正确**的数字，不是退步。
