# 阶段 K：方块图改成「一张平面图，单击原地展开」（2026-10-08）

## 0. 用户原话（最高优先级）

> 方块里面的交互逻辑，我觉得还是有点奇怪。不要做成一层一层进入的逻辑，而应该是一个平面。
> 因为做成双击进入的话，很多用户可能根本发现不了。我觉得还是单击直接展开显示更深的层级，类似 SpaceSniffer 那样的逻辑就可以。

SpaceSniffer 的做法：单击一个文件夹块 → 它在原位置显示出自己的内容，继续单击里面的块就继续往里挖；双击才是放大到整个视图。
我们只要「单击往里挖」，**不要双击进入**。

## 1. 现状（要改掉的）

- `TreemapView.vue`：方块图的根 = `store.listing`（当前文件夹），画两层；单击只能选中**顶层块**（点里面的小块也是选中它的顶层父块），**双击才进入**（`enterBlock` → `openDir(path, path)` 换根）。
- `store.ts`：`openDir / setFocus / enterRow / enterBlock / goUp`，面包屑 `crumbTarget` 换根；第一次进分析页自动选中最大的子文件夹。
- 后端 `get_treemap(path, depth≤3)`：每层最多 300 / 80 / 40 个子项，小的并进 `hidden_bytes / hidden_count`，阈值相对于**请求的那个根**。

## 2. 新交互（定稿，照做）

**术语**：展开链 `chain` = 从方块图的根往下、被单击挖开的那串文件夹路径（`[p1, p2, …, pk]`，p1 是根的子文件夹）。`pk` = 当前展开的文件夹。

1. **方块图的根始终是扫描的根（整个盘，例如 `C:\`）**。单击不换根，所有东西都在同一张图上。
   - 唯一例外（自动缩放）：展开链超过 3 层时，图的根悄悄下移到 `p(k-3)`，保证最深那块够大；面包屑仍从盘根开始，点上面的级别会回到对应层（根跟着移回去）。
2. **单击任意深度的文件夹块 = 往里挖**：展开链变成「从根到它」。
   - **原地变大**：链上每个文件夹至少占到它父块内容区的 `BOOST = 0.6`（本来就更大就不动）；兄弟块按原来的比例挤在剩下的空间里，**仍然看得见**。
   - **显示更深的层级**：它里面的子项、孙项在有空间的地方画出来（容器 = 带标题栏的块）。数据不够深就懒加载（见 §4）。
   - **动画**：块的位置 / 大小用 CSS 过渡（约 260 ms，`var(--ease)`），新出现的块淡入；`prefers-reduced-motion` 时不动画。要让人看得出「是这块在原地长大」。
   - 右边列表（并排 / 列表视图）跟着显示 `pk` 的内容；面包屑 = 盘根 → … → `pk`。
3. **单击文件 / 「其他 N 项」/ 无权限·系统保留等伪块 = 选中它**：展开链设为它的父文件夹（已经是就不动），这块描粗边高亮；右边列表定位到对应那一行并展开它的说明（伪块 / 其他：只高亮，不展开行）。
4. **收起**：
   - 单击**已展开**（在链上）的容器的**标题栏** → 收起到它的父级（链截到它之前）。
   - 面包屑点第 i 级 → 链截到第 i 级（第 0 级 = 全部收起）。
   - `Esc` = 全部收起；`Backspace` = 收起一级（替换原来的 goUp）。
   - 单击另一个顶层块 = 展开链换到那边（原来的自然收起）。
5. **双击不再有单独功能**：双击 = 两次单击，第二次单击如果落在 300 ms 内、且第一次刚触发了展开，就忽略（防止一次双击连挖两层 / 挖了又收）。
6. **键盘**：块可以 Tab 聚焦；Enter / Space = 单击。
7. **一进分析页**：什么都不展开（链为空），方块图按真实比例显示整个盘，右边列表 = 盘根。（取消原来的「自动选中最大的子文件夹」。）
8. 列表里文件夹行右端的「›」= 在方块图里展开这个文件夹（链延长一级），不再换方块图的根。列表视图（不显示方块图）里也一样，靠面包屑和「›」走动。

## 3. 外观（Opus 美术指导：只加必要的状态，不加文字）

- 屏幕上**不加任何说明句子**；可点性靠：鼠标变手形、悬停时块的描边加深 / 轻微提亮（三套主题各自的 token）。
- 链上的容器：标题栏加强（A/B：标题字用 `--ink`、加粗；C 卡通主题：标题栏底色用主题强调色、墨黑描边），最深那个（`pk`）用现有的 `.sel` 粗边；链上祖先用比 `.sel` 弱一级的「已展开」样式。
- 被选中的文件 / 伪块：沿用 `.sel` 粗边。
- 块的大小数字始终是**真实大小**（放大只改面积，不改数字）。
- 悬停卡片（tip）不变；容器块（现在 tip 不显示）保持不变。
- 三套主题（A 浅色 / B 深色 / C 卡通，用户用 C）都要好看；参照阶段 I 的 tileBox 规则（圆角 / 描边 / 投影按块大小收敛）。

## 4. 数据与布局

- **布局（`src/treemap.ts`）**：`TmInput` 加 `boost?: number`（目标最小面积占比）。`place()` 里给带 boost 的那个子项一个**有效权重** `eff = max(value, boost/(1-boost) × 其余兄弟（含其他/隐藏）的合计)`，squarify 用 `eff`；输出的 `TmItem.value` 仍是真实值。每个父块最多一个 boost 子项（链）。小块合并成「其他」的逻辑照旧（按像素判断）。
- `maxDepth`：不再固定 2 层；链上的文件夹允许往下再画 2 层（`pk` 的子项和孙项），其余地方照旧（有空间就画到数据的深度为止，`minContainerPx` 控制密度）。
- **懒加载 + 拼接（graft）**：挖到某个文件夹 X 时，如果当前树里 X 下面不够两层，就 `getTreemap(X.path, 3)` 取它的子树，替换掉 X 的 `children / hidden_*`。按路径缓存（大小写不敏感）；新扫描 / 清理之后（`reloadViews`）清缓存、按链重新取，链上不存在了的路径就截掉。取数据期间不挡操作（可以有轻微的 loading 态）。
- 「外壳」合并块（`Users \ king`，`collapseChain`）：单击它 = 链加上 Users 和 king 两级；boost 加在这块上。
- 自动缩放后根不是扫描根时，没有伪块（无权限 / 系统保留 / 未归属）——和现在进入子文件夹时一样。

## 5. store 接口（建议，可调整，但要有测试）

- `chain: Ref<string[]>`、`mapRootPath`（computed，自动缩放规则）、`tm`（拼接后的显示树）。
- `digTo(path)`：设链为「根 → path」（祖先用 `listDir(path)` 的 breadcrumb 得到），拼接数据，`focus` = `listDir(path, 200)`。
- `collapseTo(i)` / `collapseOne()` / `collapseAll()`、`selectLeaf(path, kind)`。
- 删掉 / 改写：`enterBlock`、`enterRow`、`goUp`、`crumbTarget` 的换根语义；`openDir` 可保留为内部函数。
- `store.nav.test.ts`、`treemap.test.ts` 跟着改；新增：boost 后链上块的面积占比 ≥ 0.6×（父内容区）且块不重叠、不出界，兄弟顺序 / 比例保持；值不变；digTo / collapse / 双击防抖 / 自动缩放 / reload 截链。
